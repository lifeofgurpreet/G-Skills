# This release's support scope

This file travels with the installed VPS Health version. It is a technical-preview
support boundary, not a live status page or a claim that the skill is airtight.
Read the installed `skill.json` for its version. Repository updates and another
skill's passing checks do not retroactively qualify this installation.

## Useful, implemented core

The Linux passive collector, retained SQLite history, local evidence workbench,
owned bounded start/stop lifecycle, interrupted-setup recovery and private reports
have real process, browser and extracted-archive tests. The existing-monitoring
route has bounded source, retry, empty-response and gap tests. Each user's actual
endpoint, access and exporter coverage still need verification by their agent.

A CPU-accounting result is not proof of provider responsibility or good application
performance. Workload context carries its own coverage and currentness. Guest
fingerprints do not attest a physical host or establish that a migration was fake.
Normal private snapshots are not public-safe support attachments; `support-report`
contains a deliberately smaller set of categories, counts and software versions.

## User-agent routes and present limits

| Route | What was exercised | What is not established |
|---|---|---|
| Python CLI and Linux lifecycle | Actual installed subprocess, HTTP and database outcomes, with source-bound stop/recovery | A customer's workload, permissions, filesystem and service behavior |
| Claude Code | Prior version-specific explicit-entry setup/resume/stop and project discovery/removal/restoration | Current-version paired task quality and trigger reliability; latest comparison attempts stopped at expired OAuth before inference |
| Codex | Layout, instructions and prepared acceptance cases | A completed native user journey; the recorded authentication failure was not successful execution |
| Mac/Windows | Selected portable demo, offline or foreground paths | Linux-local counters and the managed Linux lifecycle on these operating systems |
| Remote browser path | A separate draft has native Mac/Linux SSH and HTTP evidence | That unpublished draft is not part of this installed release; external-link/browser acceptance remains open |
| Mail support | Local provider draft commands, minimal software diagnostics and instructions for host-native connectors | End-to-end OAuth/send reconciliation in every host; no sender or OAuth service is bundled |
| Long observations | History retention, interval qualification, gap handling and replay | Completed representative 72-hour live trials on both standalone and existing-monitoring routes |

A previous account or sandbox failure does not imply failure in every user's
environment. It means that route has not earned an unconditional support claim.
The host agent should check the actual environment and give one concrete missing
access/dependency question rather than bypass permissions or invent results.

The temporal analyzer, inline channel-coverage captions, Evidence duration view
and pinned review are implemented against the same source profile. They preserve
missing/stale context instead of inventing a new frontend score. The CLI can also
verify its own multi-file summary exports without claiming those summaries include
raw replay. Current-version browser/process checks still do not establish every
native agent workflow, external mail result or completed field pilot.

## A successful first use

The agent resolves the installed CLI from `SKILL.md`, checks capabilities without
creating a workspace, and confirms the authorized target. For a demonstration,
it uses synthetic observations. For real collection, it gets the necessary
bounded-scope approval, reuses or starts one owned run, and verifies both the
process and the viewer reachable by the user. It then reports the actual evidence
state and stop/resume path. Missing access stays explicit; a command list, installed
folder or recognized skill is not completion.

Authored eval prompts and artifact checks are available for improving this workflow.
The prepared trigger set and blocked paired runs are not model benchmark scores.
Do not tell a user the skill improves every model or can be run unattended on any
host merely because its YAML parses and its deterministic tests pass.

## Community publication

An accurate description is: **VPS Health helps a coding agent set up a private VPS
investigation, compare CPU accounting with measured workload context, retain the
evidence and prepare a useful next step. Technical preview; support is scoped.**

It does not guarantee provider migrations, identify a noisy neighbour conclusively,
prove guest innocence, authorize downtime, contact anyone automatically or promise
popularity. The human decides whether to post, invite testers or send a reviewed
message. A new release tag is not that separate external-action decision.

For details, read [the agent action map](agent-actions.md),
[time qualification](time-evidence.md), [support](support.md) and
[correspondence](correspondence.md) only as required by the current task.
