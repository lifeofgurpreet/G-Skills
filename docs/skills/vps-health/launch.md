## Longer community introduction

I built VPS Health because a slow server is not enough information to know what
to fix. It gives a coding agent a repeatable way to set up a private investigation,
retain observations and show CPU accounting alongside workload context.

The useful part is not a single score: missing coverage stays visible, the
attention inbox points to the next check, and a minimal support report helps you
ask for help without publishing the whole investigation. The human approves the
target, access and consequential actions; the agent performs routine setup.

It is the first published skill in my G-Skills collection. It is a technical
preview, with the tested routes and remaining qualifications documented. The
video uses the actual product with synthetic examples, not a customer's fleet.
I would value reproducible feedback and contributions from people operating VPSes.
Please use the minimal report and avoid posting credentials or raw private data.

## What viewers are seeing

The media tool creates a fresh built-in demo, uses the real browser interface to
select subjects, move the linked chart cursor, open Attention and download the
support report, and captures those resulting UI states. It cannot accept an
existing customer workspace or arbitrary URL. Its requests stay on the temporary
loopback viewer. The viewer and fixture are closed afterward.

The film is **motion design over verified product captures**, not a claim that
an AI agent performed those clicks. Its plan/start/verify/stop sequence is labeled
as a workflow illustration. The support-card layout is an editorial summary of
the downloaded fields, not a fictional new screen in the application. Charts and
missing values are not edited. Persistent labels identify synthetic data and the
technical-preview stage, including when the demo displays a multi-day window.

Actual Opus 5.5 was used for the creative brief/storyboard through the existing
protected account route. Its contribution was text-based creative direction and
claim review; it did not independently operate, verify or render the product.
The sanitized receipt identifies the actual returned model and trace hash, not a
self-reported model name pasted into promotional copy. Private native traces stay
outside public source.

## Rebuild, verify and share deliberately

```bash
python tools/skills/vps-health/test_launch_media.py
python tools/skills/vps-health/launch_media.py --out /private/new-launch-output
```

Rendering is developer-only and needs pinned Playwright/Pillow, a local font and
ffmpeg/ffprobe. These dependencies do not enter the installed skill. The tool
checks the skill against the reviewed release, produces both cuts, probes encoding
and duration, and decodes each complete video. Inspect the exported keyframes,
first/last frames, captions and actual playback before uploading anywhere.
The manual/PR-scoped GitHub workflow retains only synthetic media and a manifest,
not private workspaces, actual host observations or native model traces.

The format was checked against [X's video guide](https://help.x.com/en/using-x/x-videos)
and [media guidance](https://help.x.com/en/using-x/media-studio-faqs). It is also a
conventional MP4 for other community channels. Recheck the selected channel's
actual upload result; a codec check is not an already-published post.

## Stable-release acceptance remains separate

Native project discovery and prior explicit-entry Claude runs have receipts;
current sandbox execution and Codex authentication are not silently waived.
The first bounded passive development-host pilot is now running, not completed.
Its private observations must accumulate for the full window and its companion
existing-monitoring route still needs qualification. These facts do not prevent
sharing an honestly labeled technical preview, but they do prevent claiming the
broader `gs-2uh.13` stable/promotion gate is complete.
