# 0.5.0 — Operator journey: research and verification

This release answers the missing question after a chart: what should an operator
or coding agent do next, and what is it actually authorized to do?

## Research applied, not copied

Five additional installed skill entry points were studied in applicable sections:
CLI doctor design, documentation architecture, README writing, software research
and stateful SQLite CLI design. The [applicability receipt](improvement-v0.5.0.json)
records source hashes, read ranges and code/test mappings. A repository-specific
archive workflow was also inspected and rejected as irrelevant. An index is not
a claim that every skill was read, and selected guidance is not completion of a
large external audit framework.

The main adopted patterns are diagnostic-first CLI behavior, a runnable first
user journey, one evidence authority, explicit missing-state handling, and tests
for the actual exported artifact. We deliberately did not copy another author's
contribution policy, paid text, automated fixers, multi-agent ceremony or hosted
documentation stack. Public prose and implementation are original.

Installed pstack's actual-output verification, subtraction and structural-lesson
principles shaped the implementation. The old workspace CSS was replaced, not
retained alongside another theme. Attention is derived from existing evidence,
not a second decision engine. Repeated failure cases become tests, not more
warnings that the next agent can forget.

## Changed operator paths

- `doctor` is read-only and offline. It checks local configuration, chart integrity,
  a bounded real SQLite quick check, credential-variable presence and evidence
  readiness. No daemon-liveness inference, API probing or repair is performed.
- `brief` and the dashboard use the same prioritized findings. Quality problems
  precede performance; an acceptable accounting mean can still surface pressure.
- The new layout adds an interval evidence ribbon, attention inbox, setup routes
  and dated provider references around the existing linked uPlot charts.
- Acknowledgment is session-local unread state only. Recovery removes it, so a
  later recurrence is visible. New desktop alerts require a click and permission,
  only run while the viewer is open, and do not expose node details on screen locks.
- Plan-question drafts are separate from evidence-gated performance-review drafts.
  Both require explicit approval, remain local and never send or authorize changes.
- The demo includes variable execution and intermittent pressure/throttling so
  the context panes demonstrate an investigation rather than decorative flat lines.
  Its accounting verdicts and synthetic designation remain unchanged.

## Failures reproduced and corrected

The baseline lacked doctor/brief/provider workflow commands. Their initial contract
suite failed because that module did not exist; this is a missing capability, not
23 independently discovered production bugs.

A browser regression then reproduced a real state defect: a resolved finding that
returned inherited its old acknowledgment. A separate unit case showed that good
accounting could omit elevated workload pressure from attention. Both were fixed
in the owning state/brief paths. Malformed operator payloads are rejected before
replacing a valid screen. A slow in-flight refresh now shows a disabled busy button,
so another click is not silently swallowed. Fractional timeline boundaries are
covered without inventing elapsed observation time.

A final malformed-configuration check reproduced an AttributeError for a list-valued policy or non-object asset. Both now return a structured unavailable diagnosis, leaving every workspace file unchanged. The two additional regressions run against real private workspaces.

Two plan-question cases initially failed because the only draft path required a
performance result. The new purpose asks about an explicitly supplied plan and
makes no performance allegation; the original performance evidence gate remains.

## Executable verification

The Python suite comprises 174 tests: 46 collector/report, 56 prior workspace,
11 private-study, ten chart projection, 39 operator/diagnostic/communication,
six vendor-integrity and six release-package contracts. Twelve JavaScript chart
adapter contracts remain in place. The existing browser suite is expanded to
27 scenario groups against the real loopback server and actual synthetic SQLite
workspaces. It covers navigation, charts and export, setup recipes, provider
filtering, acknowledgment/recovery, delayed and malformed refresh, 100 configured
subjects, 320–1440px layouts and a touch-enabled browser context.

The operating-system notification constructor/permission boundary is deliberately
simulated in browser tests. Actual permission prompts and delivery on every OS are
not claimed. Real DOM actions, network refreshes, local server behavior and data
storage are exercised separately. Synthetic fault injection is used for failure
cases; no private production endpoint is a test fixture.

Tests on the authorized development host use an isolated private TMPDIR because
that host's shared /tmp is itself inside a Git worktree. The private-study guard
was not relaxed to make its test pass. Final release-source CI is required; an
earlier green source hash is not substituted for a later change.

The release builder verifies the actual ZIP root, required operator assets,
project/vendor licenses and deterministic hashes, extracts it, then exercises
standalone bootstrap, export, doctor, brief and provider commands. No repository
checkout or developer browser tools are runtime installation requirements.

## Remaining unknowns and limits

This is not a multi-day real VPS field trial or a universal provider-cause detector.
CPU accounting does not diagnose network loss, disk latency, application errors or
EC2 credits without those additional instruments. Provider documentation is a
dated reference, not an inspection of each user's actual contract or a tested
cloud API integration. Contabo product summaries were read from indexed official
sources; direct page retrieval was unreliable and is not claimed complete.

The viewer is loopback-only and read-only. It cannot run setup commands, send an
email, install a notifier or start collection. An approved collector can continue independently of the browser; desktop alerts cannot. No physical-phone test, full
accessibility certification, independent model review or universal skill-discovery
success score is claimed. These require separate qualification, not a larger
marketing adjective.
