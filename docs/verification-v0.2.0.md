# v0.2.0 verification receipt

## What this release adds

A persistent private workspace around the existing collector: demo/local/fleet
bootstrap, content-addressed SQLite history, a local live dashboard, daily UTC
rollups, bounded foreground monitoring, generated user timer files, immutable
summary exports, optional reviewed email drafts and sanitized learning proposals.
No service installer, provider sender, stress runner or cloud mutation is added.

## Executable checks

`python3 tools/validate.py` passes **93 tests**: 46 original collector/report tests
and 47 workspace tests. CI invokes the same entrypoint on Python 3.10 and 3.12.
The validator also copies only the skill directory to an isolated location and
exercises demo, original replay, bootstrap, dashboard, export, learning and the
non-sendable draft example through the actual CLI.

Tests use synthetic counters, a real bounded loopback Prometheus HTTP endpoint
and the actual local dashboard HTTP handler. Important failures were reproduced
before correction, not merely asserted on the final implementation:

- Owner epoch or exporter binding changes cannot reuse an old healthy result.
- A failed or empty latest collection cannot refresh an older observation.
- Overlapping query windows do not add duplicate hours or overwrite conflicts.
- A point at the query start cannot add an interval preceding the capture. The
  end-to-end HTTP test first exposed 65 minutes represented by a one-hour query;
  interval clipping corrected it while preserving the original raw response.
- A long planned watch is rejected before collection, and simultaneous writers
  are refused rather than racing the private database.
- The browser cannot read arbitrary files, credentials or raw logs and cannot
  mutate the workspace. Drafts require approval; incomplete examples are marked
  non-sendable. Learning retains whitelisted aggregate categories, not identities.

The workspace holds raw capture bytes separately from normalized interval
coverage. Report views remain bounded; retained compressed raw bytes stop at the
configured implementation limit rather than being silently pruned. No test turns
HOLD into permission to contact a provider or modify a machine.

## Browser and real passive checks

The exact dashboard template SHA-256 was:

```text
28002d149f84d167fa7df130a931bcebc10017723ba37944c4afb7837e87b853
```

Playwright/Chromium rendered that template with a synthetic status generated by
the shipped workspace code. For transfer into the browser-test environment, chart
points were reduced; summary statistics were not changed. Checks covered three
subjects, a two-subject attention filter, details expansion, three history graphs,
daily rows, synthetic watermark and no horizontal overflow at 1440px and 390px.
There were no JavaScript exceptions. The browser-test environment disallows
`file://` navigation, so rendering used `set_content`; that check is not a claim
of browser file-route qualification. Separate executable tests exercised the
actual loopback HTTP viewer and access restrictions.

On an authorized Linux execution host, an explicit two-cycle passive smoke run
at a 60-second cadence completed with zero failed cycles. It retained about one
minute of observations, reported HOLD, and did not establish provider causality.
No multi-day or fleet result is inferred from this smoke check. Its identifiers
and actual telemetry remain private. No collector is left running by this test.

Gitleaks and structural checks passed for the publication tree. The repository
contains synthetic examples and original implementation, not private operational
captures, credentials, provider correspondence or paid skill text.

## What is not certified

This is not a multi-day field qualification, an independent model review, an
internet-facing web service, or a provider-causality classifier. User-timer files
were generated and tested, not installed on hosts. Unrun behavioral agent
scenarios remain explicitly distinct from executable test results. Backing up an
active SQLite file, performing stress experiments, exposing the viewer publicly
or sending any correspondence requires a separate reviewed workflow.

The public JSM packaging principles and installed pstack verification/domain
leaves informed the workflow: demonstrate first, preserve uncertainty, encode
recurring corrections in tests, keep one existing collector and a small workspace
layer, and prove the output through the real entrypoint. No paid content was
copied and no automatic self-modification or public upload was enabled.
