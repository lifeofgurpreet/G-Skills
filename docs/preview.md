# VPS Health preview: the support claim is narrower than the feature list

VPS Health is one independently versioned skill in G-Skills. Public source and
releases already exist. This document describes a technical preview, not a claim
that every agent, OS, provider or multi-day field scenario has been certified.
Publishing a source artifact is not permission to announce or email people.

| Route | Evidence | Remaining boundary |
|---|---|---|
| Linux standalone/demo/managed workflow | Real subprocess, HTTP, SQLite and extracted-release tests | Synthetic fixture results are not a multi-day real-server trial |
| Existing Prometheus route | Bounded loopback source, retry, gaps and identity tests | Each user's endpoint, authorization and exporter coverage must be verified |
| Claude Code explicit entry | Earlier real setup and separate-session stop trace | That receipt is version/environment-specific, not universal discovery proof |
| Claude Code project skill discovery | Native discovery, loading and removal/restoration checks in a private project | Current execution session hit a required-sandbox dependency failure; no bypass or package installation was attempted |

| Mail/other connectors | Host-native request/handoff contract | Actual OAuth and external-write reconciliation remain separate gates; no sender is bundled |
| Multi-day assessment | Retention, gap and replay logic tested | Completed 72-hour representative pilots remain open |

## What a user should do

Give the full chosen skill directory to an authorized terminal coding agent, not
just its markdown. Ask the agent to install/reuse it through the client's supported
project or personal location, identify the authorized target, and show a synthetic
preview before collecting real observations. The agent should execute routine
configuration and verification. The user supplies missing scope, authentication
and consequential approvals.

A configured CLI, installed folder, recognized skill or success-shaped model
response is not proof of a running viewer. Use the actual `agent-verify` result
and distinguish it from evidence quality. If the client's sandbox cannot start,
report that blocker and preserve the work; do not turn a security setting off to
make the demonstration pass.

## Before wider promotion

The existing preview gate `gs-2uh.13` still requires genuine native-client, safe
installation and sustained-pilot acceptance. Optional mail sending, active
experiments and every provider are not required when excluded from support claims.
The [native task graph](skills/vps-health/ROADMAP.md) is authoritative; this page is
not another copied progress tracker. Use [SUPPORT.md](../SUPPORT.md) for safe feedback.


## Known workload-context acceptance gap

`gs-2uh.15` tracks a reproduced issue: a quiet pressure/throttling mean may be
computed from very few or old samples even when CPU accounting spans several days.
The workload-context summary can therefore appear more complete than its channel
coverage supports. Do not use that summary to rule out guest workload constraints
or assign provider responsibility; inspect the underlying same-window channel
coverage separately. The accounting observation and provider reference are different
claims. A failure-first test branch is retained; the proposed implementation was
blocked and is not included in this release. The existing broad-promotion gate
remains open. This paragraph is a limitation, not a claim that the bug is fixed.
