# Support for G-Skills

Name the skill, its version, the coding agent/version and the operation that failed.
Each skill has its own supported environments and evidence; installing one does
not grant access to services or imply support for every terminal agent.

**Do not post credentials, account identifiers, private repository content, host
inventories, raw traces, dashboards, databases or provider messages in public issues.**
Use synthetic reproductions. A normal export is not automatically safe to publish.

For VPS Health, ask your agent for `support-report`, or use Support report in the
live viewer. Review the resulting versions, categories and counts before sharing.
The command sends nothing and deliberately excludes raw observations and identities.
The [skill support guide](skills/vps-health/references/support.md) explains its limits.

A client reporting that a required sandbox/dependency cannot start is an environment
boundary, not permission to disable the sandbox. Describe the categorical blocker;
never paste token values or switch accounts to manufacture a passing result.

Bug reports belong in the repository's bug form. Suggestions should name an actual
user outcome and which skill owns it. Security-sensitive material follows
[SECURITY.md](SECURITY.md); do not assume a private-reporting service is enabled
without checking it. Maintainer review and response time are not guaranteed.

[Current preview scope](docs/preview.md) records what has and has not been exercised.
The public source can be tried without treating unfinished compatibility or
multi-day validation as already passed.
